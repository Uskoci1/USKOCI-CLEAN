# Home restart after owner references

Owner explicitly named Airtasker, Taskrabbit, Wolt, Airbnb and Uber as attractive references. This supersedes the generic visual judgement behind the rejected A/B/C exploration.

The existing Home model gives an account its obligations and two entry actions. The restarted composition explores a small public-task preview alongside those responsibilities. This is a UX proposal, not an installed feature: it requires a bounded existing-search integration, explicit location/remote fallback, loading/unavailable states and correct task relation before any native implementation. No ranking, ratings, verified users, exact location or payment guarantees may be invented.

Three new compositions were explored and revised before implementation: (D) a task-description entry with one primary action, then earning and discovery; (E) two equal entry panels, filters and an illustrated public-task feature; (F) obligation-first workspace, a next-agreement panel, then entry actions and discovery. Discovery content and the agreement are explicitly synthetic design content, never DEV data. F shows a busy account; D/E show accounts without personal activity. This is not a controlled comparison of identical states.

Style studies use Manrope only in Figma. Existing native font dependencies remain unchanged. The 3dicons v1 notebook (CC0, Vijay Verma, image hash e6d576f66f2cf660d82682eb3cec231ce63d8f5b) and original vector scene remain unused studies. Delivered screens use Microsoft Fluent Emoji chair, package, laptop and potted plant assets as category illustrations, not photographs of actual task property. Their source repository is https://github.com/microsoft/fluentui-emoji and its MIT license is preserved in the output assets directory. Owner reference screenshots remain reference-only and are not copied into USKOČI.

- Browser verification: gallery loads; selecting the second proposal shows it alone; returning to comparison restores all three. No native tests were run because no native code changed.
- Not verified: all attention reasons, partial/failed/empty public search, pending receipts, 200% text, reduced motion on a device, small native screens, screen-reader semantics, functional prototype navigation. No code/state completion claim is made.
- D's example text represents an entry into the existing AI task-creation flow; it must not be submitted automatically. If implemented as editable input, local draft ownership and explicit submit must be designed.
- Public-task discovery on Home is a proposed additional read, not a claim that the existing Home already provides it. It requires bounded search, location consent/manual or remote fallback, relation-aware routing and honest failure states.
- F's agreement panel is a route to an existing agreement, not a completion action or evidence of money transfer.
- Prior recommendation A remains withdrawn. D/E/F are unapproved; do not propagate them across the native app as an approved design system.
