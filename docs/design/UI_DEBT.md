## Separate engineering issues, not visual fixes

- Home aggregate is installed but client collection scanning remains. Treat wiring/count parity/paging as explicit data work, separate from the new composition.
- Existing review/backend functionality cannot be declared absent because an earlier reviewer missed its screen.
- Claude's candidate migration and identity-gating change require independent engineering review. Do not apply them as part of UI cleanup.
- Connection-service monetization is undecided. No mock wallet, escrow, purchase success or per-person price activation.
- Potentially unused components need an import/platform/export/test audit; no blanket deletion of legacy-named routes or test fixtures.

## Verification policy

Static proof is sufficient to record UI-03/04/07/14; it is not a claim that those scenarios were executed on the phone. The screenshot filenames and source snapshot are recorded in CURRENT_UI_TRUTH.md. Calculated contrast follows [WCAG non-text contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html); no full WCAG conformance claim is made.

After design approval, first fix important interaction/recovery defects with focused tests alongside the affected surface. Use actual-device visual QA for geometry. Run project checks at the appropriate integration boundary. Never mark an item closed merely because a component renders or a build passes.
