## 7. PRODUCT INTEGRITY GAP SWEEP — BEFORE ADDING ANY NEW FEATURE

Classify every newly discovered gap into exactly one of:

### A — LAUNCH/SAFETY REQUIRED
Without it, a core journey is broken, misleading, unsafe, insecure, non-compliant, unrecoverable or not store-ready.
Implement it when semantics are derivable from canon/security and it does not require a new owner business decision.

### B — PRODUCT-COMPLETE SHOULD-HAVE
It materially improves the intended V1 journey and fits existing canon/surfaces without creating a new business model.
Implement when dependency-safe and justified.

### C — OPTIONAL / POST-LAUNCH
Nice feature, competitor feature, optimization or extra complexity not needed for the V1 journey.
Do not let it block launch.

### D — DECISION REQUIRED
It changes pricing, marketplace semantics, roles, privacy, liability, authority, paid behavior or creates a genuinely new product state.
Do not invent the decision. Isolate it and continue independent work.

Before creating a new surface/table/state, answer:
1. Which exact user problem does this solve?
2. Which existing journey does it complete?
3. Can it be solved inside an existing surface through progressive disclosure?
4. Does the backend need a new durable state or can existing authority represent it?
5. Is it launch-required or simply attractive?

Feature completeness does NOT mean more features.
It means no broken essential journey.
