CLEAN has no record of which Terms and Privacy versions an account accepted, no registry of published legal documents, and no way for S03/S07 to show legal links from server truth. The donor closed this in `rc2_021_versioned_legal_consent_ledger` (195 lines); the master's donor→CLEAN reconciliation marks it ADAPT_HIGH. This unit ports that design onto CLEAN authority as a forward-only migration: two tables, two owner RPCs, no schema change elsewhere.

Rebinding. `private.r24_require_user()` is replaced by the inline `auth.uid()` / `AUTH_REQUIRED (28000)` check used across CLEAN; `clock_timestamp()` by `statement_timestamp()`; RPC names follow the semantic convention (`rpc_get_legal_bundle`, `rpc_accept_legal_bundle`). The `references public.app_accounts(id)` foreign key binds unchanged because `app_accounts.id` equals `auth.users.id` for every account. One improvement over the donor: a `pg_advisory_xact_lock` keyed on account and request id serializes a same-key race into one row plus one replay instead of a unique-violation error. First acceptance writes a `LEGAL_BUNDLE_ACCEPTED` row through `private.audit_marketplace` with entity type `SYSTEM`.

Contract. `rpc_get_legal_bundle()` is readable by `anon` and `authenticated` so legal links can render before sign-in; it returns `ready:false / LEGAL_DOCUMENTS_NOT_PUBLISHED` until both an active TERMS and an active PRIVACY row exist, and `acceptedCurrentBundle` only for the signed-in account and only for the exact active versions and hashes. `rpc_accept_legal_bundle(text)` is `authenticated` only, validates the request id (16–96, `[A-Za-z0-9_-]`), records an immutable snapshot of both document ids, version labels and SHA-256 hashes, replays the original receipt for the same id, and refuses the same id on a different bundle (`LEGAL_ACCEPTANCE_REQUEST_REUSED_FOR_DIFFERENT_BUNDLE`). Both tables have RLS enabled and forced with all privileges revoked from client roles; there is no direct table path. Registry constraints: one active row per kind (partial unique index), 64-hex SHA, https URL, effective ≥ published, active rows cannot be retired.
