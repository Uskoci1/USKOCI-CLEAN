# P2 export delivery — source connected, disposable proof pending

The existing data-export request ledger now has a complete technical delivery path: an explicit S09 request, a server worker, a private JSON artifact, authenticated download, native file saving, revocation and exact-object cleanup. SQL104 extends the existing P2 request and P3 policy owners. It introduces no second request ledger or parallel legal policy registry. The original intake contract remains independently proved at source103 before the intentional delivery extension.

S09 is reached from Profile in both intent modes. It reads actual request status, keeps the same request key after an uncertain write, prepares only on user action, and enables download only for a validated current artifact descriptor. Account incarnation, focus, generation and expiry retire old callbacks. Late download buffers are cleared. Native saving uses the selected directory, refuses overwrite, and confirms the written size and MD5. The browser verifies SHA256 and reports download started; it cannot establish where the browser saved the file. A revoked server copy does not recall files already saved by the user.

The worker authenticates the user and derives the account from Auth before a service-only claim. It uploads the exact immutable snapshot text, reads the actual private Storage bytes back, verifies SHA256, and only then completes the fenced attempt. The download handler obtains an owner-bound grant, verifies Storage bytes and re-resolves the grant before releasing the buffered file. Tokens remain in headers; Storage paths, service credentials and signed URLs are not returned to the client. Both handlers enforce bounded requests, isolate-level rate limits and deadlines. No raw response bodies or credentials are logged.

Attempts have unique immutable object paths. Expired leases can be reclaimed; stale attempts cannot complete or revoke their replacement. An uncertain completion never triggers opportunistic deletion. Cleanup checks the exact object and accepts only a recognized missing-object response as absence. Retired paths remain eligible for periodic reconciliation because an already-issued upload can commit after an earlier absence check. The 60-second reconciliation interval is technical scheduling, not a chosen legal retention duration. Global work skips busy accounts and oversized snapshots without truncating an archive.

Artifact, temporary snapshot and download lifetimes must be configured; no legal durations or policies are seeded. The JSON projection includes only explicitly admitted owned fields. Media is metadata only and explicitly says `bytesIncluded:false`; full account completeness is not claimed.
