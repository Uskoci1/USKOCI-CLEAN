## N01 — narrow implementation candidate

`supabase/proofs/notifications/n01_message_event_candidate.sql` replaces only the existing message writer in a disposable instance. It is deliberately **outside supabase/migrations** and is **not production-admitted**. The exact predecessor body MD5 is `705f19630e27792639d737bfa41d77c6`; an unexpected body or missing emitter aborts. Existing signature/return UUID, Auth/participant/state checks, admitted 2000-character message bound, trimming, insert and grants remain byte-equivalent except one call before return.

The existing `private.emit_event` derives channel behavior. N01 derives recipient and role from Agreement binding, uses MESSAGE_RECEIVED/AGREEMENT/current version/NORMAL and a per-persisted-message dedupe key. The payload contains only message_id; delivery copy is generic and contains no message/task/contact/location content. Errors propagate so message and event commit or roll back together. No duplicate notification implementation, provider, service key in mobile or business policy is added.

**Idempotency scope:** a repeated internal emission for the same persisted message does not duplicate its event/deliveries. Repeating the current send RPC remains a separate message because its signature has no client command key; N01 does not claim to solve unknown-outcome message retry semantics.

The new workflow uses the unchanged historical-live-79 reconstruction and existing two-account fixture. After strict loopback guard it applies this candidate and executes real anon-key authenticated Application/selection/message RPCs. An Admin client only creates an unrelated third Auth fixture for denial tests. SQL assertions and temporary fault injection occur solely in disposable DB. No N01 operation is called a physical UI test; the already accepted physical proof is untouched.

Proof cases: both directions and bound roles; default PUSH_OFF; category suppression while preserving event; quiet hours including NORMAL not bypassing an urgent opt-in fixture; explicit transport opt-in (CREATED, not SENT); all channels off with event retained; RLS and non-party/anonymous/empty/missing/length/terminal rejection; direct message insert denied; per-message emitter replay; failure-trigger transaction rollback and recovery; real cancellation expiring pending deliveries; no push attempt; all nine gated/retired inventories zero; P0D03 free semantics unchanged. The all-day quiet-hour fixture is not a new product policy.

Runtime status is determined by exact-head `N01 Agreement message durable event proof` run and `N01-MESSAGE-EVENT-AUTHENTICATED-EVIDENCE` artifact, not this design text. Merge requires reviewed PASS artifact plus PRE-P4 and actual CodeQL result. Even after such source merge, N01 remains **CANONICAL-ONLY / disposable-proven candidate**, not LIVE. A future separately reviewed forward migration, MD5 manifest, full gates and permitted fresh live preflight are mandatory for production promotion.
