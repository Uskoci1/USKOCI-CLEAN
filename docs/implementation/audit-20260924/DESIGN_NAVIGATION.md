## Findings

### DN-01 — P2: the discovery list exposes own tasks while ownership is unknown

**Code evidence:** `src/ui/v2/DiscoveryPresentation.tsx:83` computes `shown` when the public-task read succeeds, regardless of `relationsPending`; only the count (`:198`) and first map mount (`:160`) wait. `src/app/(app)/zadaci.tsx:71` passes `relations.data ?? undefined`; the failure of that read is not presented. `src/data/marketplaceView.ts:161` returns the unfiltered public list when no owned-ID set is available. The new route deliberately retains the former “labels only” failure policy (`src/app/(app)/zadaci.tsx:41`), although ownership now decides inclusion, not just a label. The public reader in `src/data/supabaseIzvor.ts:176` supplies public tasks; it does not filter this account's own rows locally.

**Reproduction:** provide a public list containing one own task and one other task; defer `odnosiPremaZadacima`. The FlatList receives both tasks while ownership loads, without a “Tvoj zadatak” label. Resolve the owned-ID set and the own task disappears. Reject or time out that read and it remains in Zadaci. Existing `discovery-presentation.test.tsx:303` checks the withheld count, and `:331` checks the withheld map, but neither asserts that the list itself waits.

The visible refresh does not repair this state if task IDs stay the same: `src/app/(app)/zadaci.tsx:72` refreshes only the public resource. `loadRelations` is memoized on `[source, visible]` (`:53`), where `visible` is the joined task IDs (`:45`). Returning the same IDs preserves that callback and the independent resource model (`src/hooks/useFocusedResource.ts:13`); no relation retry is triggered by the public response. After inducing the relation failure, pull to refresh with the same public IDs and observe that the failed relation read is not retried. Leaving and re-entering the screen or changing IDs can trigger it, but the screen's own refresh cannot be relied on to do so.

**Impact:** contradicts the approved “other people's tasks” root and sends the person into a task that is supposed to live in Moji zadaci. This is an information-architecture defect, not a claim of a server authorization bypass.

**Improvement:** distinguish ownership-not-yet-known / failed from known-empty. Hold the initial list behind an honest loading/error state, or retain a known ownership result for unchanged IDs while re-reading. Expose a retry for the failed relation read. Do not infer “other person's task” from a missing relation response.

**Evidence level:** deterministic source-path analysis; no live account reproduction.

### DN-02 — P2 validation priority: map preview has no overflow strategy at large text

**Code evidence:** `src/ui/system/PeekSheet.tsx:48` caps dynamic height at half the window, but `:51` renders a non-scrolling `BottomSheetView`. `src/ui/v2/discovery/DiscoveryPeek.tsx:52` inserts the full TaskCard, followed by the open/close controls at `:54`; a shared point renders three rows and then “Prikaži sve u listi” (`:62`, `:71`). The full card stacks price and person at font scale >=1.3 (`src/ui/v2/TaskCard.tsx:53`), and permits a three-line title plus two-line schedule/requirement (`src/ui/v2/TaskFace.tsx:186`, `:220`). The height forwarded to map-control placement is itself clamped (`DiscoveryPeek.tsx:47`), so it cannot describe overflowing content.

**Reproduction to perform:** at 320 × 568 dp or 360 dp with enlarged text, select a pin whose task has a long title, amount, two-line time range, a vehicle/tool requirement and poster identity; also select a point with at least four tasks. Check that the lower action, close button, final row and “Prikaži sve u listi” remain visible and reachable. The installed Gorhom implementation limits the snap height (`node_modules/@gorhom/bottom-sheet/src/hooks/useAnimatedDetents.ts:80`) and explicitly allows detached content overflow (`.../components/bottomSheet/BottomSheetContent.tsx:226`), rather than introducing scrolling.

**Impact:** content can extend below the preview's allocated height into the list/tab area, without a way to scroll it into the preview. Android Back is an escape, and the task body is also pressable, so this is not reported as a proven total navigation trap.

**Improvement:** use scrollable preview content with reachable/pinned actions, or use a genuinely bounded compact preview whose remaining content opens in the task detail. Preserve the approved undimmed, interactive map.

**Evidence level:** code-backed layout risk, **not a reproduced native defect**. The viewed R3 screenshot verifies a short preview at normal size and a large-text task list, not a large-text preview or stacked-point preview. The R3 receipt explicitly leaves stacked-point interaction unexercised.

### DN-03 — P3: empty-discovery recovery opens the wrong level of profile navigation

**Code evidence:** the only primary empty-state action is “Dopuni radni profil” in `src/ui/v2/DiscoveryPresentation.tsx:186`. It invokes the same `onProfile` as the top-bar avatar (`:219`), supplied by `src/app/(app)/zadaci.tsx:73` as navigation to `/profil`. The actual worker-profile editor is `/profil/radnik`, reached under the hub label “Veštine, alat i tim” (`src/ui/profile/ProfileHubPresentation.tsx:79`).

**Reproduction:** enter Zadaci with no open tasks and choose “Dopuni radni profil”. The destination is the general profile hub, so the person must infer which differently named row continues the promised action.

**Improvement:** give the empty-state recovery its own worker-profile callback while preserving the top-bar avatar's existing hub destination.

**Evidence level:** deterministic callback/route tracing; no device execution needed to establish the destination.

### DN-04 — P3 retained accessibility debt: tab counts are visual-only

**Code evidence:** `src/ui/system/Segmented.tsx:50` supplies only `option.label` as the accessible tab name and only selection in its state; the count is drawn inside the press at `:54`, without an accessible value. This predates the audited baseline in the shared component, but the new My Applications and Dogovori presentations make the badges their count presentation (`src/ui/v2/MyApplicationsPresentation.tsx:106`; `src/ui/v2/AgreementCollectionPresentation.tsx:208`).

**Reproduction:** with TalkBack/VoiceOver, focus “Čeka te” when two applications await action. The explicit parent label exposes “Čeka te”, not the visible count. Likewise, Active/History totals are not represented by the tab's accessibility properties.

**Improvement:** keep the visible name unchanged and expose a localized count through the tab's accessibility value/label, preserving selected state and avoiding duplicate child stops. Confirm on both screen readers. This is retained debt, not a newly introduced shared-component regression.
