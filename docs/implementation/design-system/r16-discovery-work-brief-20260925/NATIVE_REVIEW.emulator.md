This makes one task look like two overlapping marker treatments. Keep the backup marker only while the rich marker is genuinely unavailable; preserve the reliable fallback if native rendering fails. 2. **People layout has a responsive gap on the phone.** The normal 411dp emulator fits. The separately reviewed 361dp/font 1.15 phone compresses “Koliko vas dolazi” to three lines alongside the fixed stepper. The next source batch should give the people label a full-width row below roughly 380dp (or when measured label space becomes insufficient), then place the stepper beneath it. Treat this breakpoint separately from the footer if appropriate. The 320dp screenshot here does not establish a people-section pass.
3. **Range end cells look square.** The 26–28 September capture shows a readable continuous range and distinct end dates, but the ends have a square fill against the otherwise rounded control language. Review the existing native calendar endpoint treatment; this observation alone does not establish an R16 regression.
4. **Map overlays still compete near the lower map area.** Attribution is readable but visually busy near pins/preview. The phone review also observed a returned cluster partly behind the sheet. Retain visible attribution and actual geographic positions while reviewing camera padding and sheet-aware placement; do not move coordinates to cosmetically hide the issue.

The white grouped filter and compact-card compositions are clear improvements in these captures, with the limitations above still open. This is a source-bound review of selected native states, not automatic acceptance of the entire product.
