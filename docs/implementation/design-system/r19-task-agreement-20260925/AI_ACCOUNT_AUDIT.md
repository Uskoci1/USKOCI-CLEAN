## Confirmed open limitations and precise triggers

1. **Closure recovery without the local START key remains an actual client gap, already recorded in control N10.** Trigger: closure was started on another device, or the original device-local journal is unavailable. `ClosureDialog.tsx:74–78` chooses a normal review when no journal exists; it does not discover an existing execution by account. `closureExecutionClientService.ts:59–61` requires the original `clientRequestId`, and `src/ui/closure/closureIntent.ts:4`, `:17` stores it only in local AsyncStorage. Impact: that client has no path to show/reconcile the previously started execution without the local identifier. This is not evidence that the worker cannot finish. The control table additionally records that restricted-account review cannot discover it; that server restriction was not freshly queried here. Correct next step: a separately proven authorized recovery contract, with any closure-certificate approval required by the owner, then a client entry. Never discard an unknown intent or delete a real account to test it.

2. **iOS dictation is not implemented by the current native adapter.** Trigger: microphone use on iOS. `src/features/voice/nativeSpeechAdapter.ts:21–24` loads `UskociVoice` only on Android and returns `unavailable` on other platforms. Impact: text remains available, but iOS cannot claim the same dictation capability. This belongs in the platform/store readiness matrix. It requires implementation and device evidence if dictation is promised on iOS; it is not a reason to label the Android text interview broken.

3. **Spoken AI answers are deliberately outside the approved first-release implementation, not a newly discovered regression.** Both AI route bodies render assistant text and use speech only to obtain user transcripts. `useHoldToTalk.ts:47` has an optional speaking guard, but neither audited route supplies a read-aloud implementation. The owner chose dictation/text first and full spoken interaction later; subsequent broad wishes do not supply a provider, dependency or paid-call decision. Do not mark full voice conversation complete or silently add it in R19.

4. **Public legal/export readiness is still conditional, not a missing export button.** Control N04/N09 records unpublished legal documents and retention rules awaiting operator/counsel input. The code correctly depends on their receipts (`retentionPolicyClientService.ts:27`, `:59`; `dataExportClientService.ts:14`; `dataExportDeliveryService.ts:12–39`). Trigger: unavailable policy, or preparation returning POLICY_NOT_READY. Impact: a user cannot obtain an available export merely because its screen and worker exist. Publication/actual worker configuration and successful delivery were not checked in this audit. Do not bypass the gate or infer current readiness from old screenshots.
