# R19 — task-led Agreements, geographic discovery and real photographs

Owner request: finish a coherent native product batch, preserve every real capability, and reconcile the application with its server, GitHub and earlier forensic reports. This package follows R18's demonstrated two-account journey. It is not whole-app or store acceptance.

## User jobs and chosen composition

| Surface | User job | Decision |
| --- | --- | --- |
| Task card / selected pin | Recognize the work and remaining capacity quickly | The visible capacity is filled/total, bottom right; complete spoken meaning remains available to assistive technology. Own tasks keep their real relationship label. |
| Agreement | Understand the accepted job and take the next permitted action | Start with a task-shaped card containing the accepted terms. Its whole face opens the authoritative source task when that ID exists. Current task edits never replace the accepted snapshot. |
| Human messages | Write to the person involved without competing navigation | Enter with the header chat icon. Both ordinary and keyboard/large-text Back return to the same Agreement overview. Unknown writes, photo recovery and terminal read-only state remain. |
| Task photographs | Inspect actual work before applying | Real photographs precede the title, use measured-width paging and an honest 1/N counter, and open full screen. No empty photo block when there are no photos. |
| Discovery | Find work in the viewed region and reach remote work independently | Keep one map/list workspace, explicit remote choice and shared non-geographic filters. Use the existing real USKOČI mark in annotations and stronger map land/water separation. |

For the Agreement, the considered alternatives were persistent top tabs, separate routed chat, and a task-led overview with contextual chat entry. The contextual entry is chosen because it removes competing header bars while retaining the existing guarded workspace and recovery state. For photos, a fixed thumbnail strip, paged cover and always-fullscreen viewer were compared; the paged cover supplies immediate evidence and optional full inspection without forcing another screen.

## Concrete functional repairs found during integration

- The actual installed Supabase Functions SDK decoded JPEG responses as text; the media service then rejected them. Contextual photo reads now preserve binary bytes, with the same session, account boundary and limits. Uploads remain unchanged. A real existing avatar is READY on DEV and has a storage object; the first R19 emulator APK now renders that stored avatar. Upload cancellation and physical-phone acceptance remain separate.
- Optional publisher metadata previously launched every distinct profile read concurrently. It now has four workers, one four-second budget, cancellation and account-revision fencing. This mitigates fan-out; it is not a server aggregate or a deadline on task pagination.
- A late safety-target lookup could navigate from a retired profile/screen or replace a newer error state. Focus/context ownership now retires it. The target RPC and actual block/report commands remain unchanged.
- Push taps now reuse the fixed Inbox destination instead of stacking copies. This does not enable push or prove transport delivery.
- Map visibility, touch and accessibility follow physical sheet position, including interrupted motion. Requested-versus-settled sheet labels can still differ after a suppressed same-index callback; MAP_AUDIT records this smaller remaining limitation.
