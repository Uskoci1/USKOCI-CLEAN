1. Both interviews end in a human-confirmed, saved result (plan 12.5 DONE; cards A02 and B00 DONE): confirmed facts survive correction, resume and review; a confirmed worker profile is saved and real criteria change eligibility as expected; draft completion is not ACTIVE.

3. Matcher uses the real conditions: hard eligibility precedes ranking, unknown capability is never confirmed capability, and every collected profile/task field has a named consumer or is not collected (plan 12.2/12.4/12.6; runbook P5 Matching paragraph).
4. A real worker -> task -> dispatch -> application/selection run passes with positive AND negative candidates; foundation/schema or a nice AI screen is explicitly not proof (plan 12.5 DONE; J03/J15; B00 step 4).
5. Persisted facts lead to bounded relevant events: no repeat send of the same opportunity, none after expiry/fill/cancel, no spam when nothing matches well, a profile/availability change has a clear consequence (plan 12.5; runbook P5 Exit 'sends bounded relevant events').
6. Corpus report states size, failures and untested categories without claiming general perfection; failures are classified (display, controller, server fact contract, prompt/provider, geocoding) (runbook P5 items 1-2 and Exit). No pass-rate number is canonical - report only.
7. Authorized real-provider samples confirm core extraction/location behavior (runbook P5 Exit) - only inside an owner-agreed budget and call count; existing recordings/proofs are used first (runbook P5 item 2).
8. Evidence levels stay separate (SOURCE / CI / DEV_APPLIED / CLIENT_WIRED / APK_BUILT / DEVICE_PROVEN / PROVIDER_PROVEN, runbook 2.1 and plan 4.2); every applied server package has exact readback and an application receipt; the certificate digest is asserted before/after.
