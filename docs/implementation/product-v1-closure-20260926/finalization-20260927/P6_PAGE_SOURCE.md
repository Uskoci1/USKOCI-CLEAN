The new RPC is `STABLE SECURITY INVOKER`, with `search_path=pg_catalog`, non-null `auth.uid()` and authenticated-only execute. It selects only already-public columns and uses existing RLS for needs, topology and conditions. Canonical `covered_slots(needs)` is pinned by normalized body MD5. No caller-visible application count replaces coverage. The existing helper at `20260830194000_clean_p2_read_layer_repair.sql:20–28` is already a security-definer count using only `n.id`; it is not rewritten here. P6 uses the same id-only `jsonb_populate_record(null::public.needs, ...)` argument as PKG045a, not `covered_slots(n)` or `n.*`. The disposable proof now requires the whole-row form to be denied after PKG045b and the id-only canonical call to succeed as authenticated. This is prepared SQL evidence, not an executed grant-boundary result. The current public membership predicate is preserved: published/selection, non-null publication instant and no remaining-search closure. Own/applied rows are not excluded.

Request validation is explicit. The normalized filter alone supplies its digest; no market-content hash or snapshot table is introduced. The 30-minute anchor freezes the query clock and publication upper bound, not mutable content. Cursor binding includes normalized scope and that anchor. Results use exact timestamp/UUID ordering and a section key; timestamps retain microseconds. A keyset page returns at most the requested 1–100 items and checks one additional row. Related public topology/conditions are projected only for the displayed page.

ALL preserves publication order. AREA and POINT_LIST append the global point-free section after matching points; equal-edge and wrapped boxes are supported. POINT_MEMBERS contains only the selected point. Remote-only normalization removes locality/geography. Counts are exact live counts from the same SQL statement/snapshot and shared predicate; they do not claim that the entire multi-request traversal is a snapshot. Global availability flags come from the anchored public collection before active filters.

`mapped` is the existing client's name for **all shared-filter matches before geographic list scope**, including remote and other point-free tasks. It is not a count of pins or `has_point=true`. The SQL `has_point` flag partitions spatial presence only. For ALL, `inArea=mapped` and `withoutPoint=0`, matching `discoveryMapScope`'s unpartitioned branch. AREA/POINT_LIST count the matched public points in `inArea` and append all matching point-free work in `withoutPoint`. POINT_MEMBERS is the contract's explicit exception: its items and all counts describe only the selected point (`mapped=listed=inArea`, `withoutPoint=0`). No current-client rewrite or semantic mismatch was found in that mapping.

Literal substring text matching keeps `%`/`_` literal. Locality unquoting, city deduplication and ECMAScript whitespace are represented explicitly. Serbian ICU lowercasing is required, not silently replaced by the server default locale. Date choices override relative words. Fixed/incomplete/flexible schedules, task-local weeks/weekends and end-at-midnight use the source semantics, including flooring microseconds before the one-millisecond end-boundary adjustment.

The allowlisted item follows the existing public reader and adds public revision. Remote items have no map point. No private address, description, account ID, resolved location or storage URL is projected. `EXACT_PUBLIC` selects one public UUID directly; it does not depend on the applied P0 reader.
