| Field | Evidence and outcome |
| --- | --- |
| Problem | Returning from task review could remount a new AI intake and lose unsent text. Backgrounding reset Agreement list choices. A failed OS-settings launch gave no usable recovery feedback. |
| Cause | Review Back replaced the original intake route identity with the newly assigned conversation ID. Agreement display choices lived inside the intentionally disposable private reader. Settings handlers swallowed native launch failures. |
| Product UX | Review returns to the same mounted intake with its original parameters and draft. Active/History and confirmation-only choices survive an ordinary foreground round trip; private rows still disappear and require a fresh owned read. Settings opening shows progress, explains failure or a ten-second timeout, and permits an explicit retry. Opening settings never means permission was granted. |
| Implementation | A bounded, account/revision/conversation-owned opaque return token restores original `entryKey`/`conversationId` parameters, with canonical fallback for stale or direct review routes. Account-keyed Agreement choice state sits above the foreground privacy gate. Shared `SystemSettingsAction` fences duplicate launches and retired asynchronous settlements, catches synchronous errors/rejections, and clears its deadline on settlement/unmount. Existing actual-permission rereads and unsaved notification edits remain authoritative. |
