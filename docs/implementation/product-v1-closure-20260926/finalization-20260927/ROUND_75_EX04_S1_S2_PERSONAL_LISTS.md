## Decisions made inside the canonical wording (disclosed; none is an owner decision)
1. **B10 order**: the registry offered two ways as a proposal; the keyset by `(rank, sortAt, id)` is the one that keeps the whole-list order with the screen unchanged, and it is proved for ties, boundaries inside a tie and between sections, and a change between pages.
2. **B10 sort key**: the whole list orders by `submitted_at` (an edited application is re-stamped), the PKG-023a page ordered by `created_at`; the page now follows the whole list. `created_at` is the fallback only where `submitted_at` was never stamped; the postflight reports any non-draft application with a null `submitted_at` as a problem (DEV has none).
3. **B10 scopes** are the screen's tabs (ALL / ATTENTION / ACTIVE / HISTORY); the old PKG-023a scopes ACTIVE / HISTORY had a different meaning and no caller.
4. **B10 signature**: the cursor gains its rank (a page boundary can fall between sections), so the 4-argument signature is replaced; this is why S2 is a DROP plus CREATE in one atomic statement and not a CREATE OR REPLACE.
5. Both readers keep the authority of their predecessors: the same own-account predicate, SECURITY DEFINER, `search_path = pg_catalog`, EXECUTE for `authenticated` only; no table, column, constraint, trigger, policy, index or data change; no new status.
