## Decisions made inside the canonical wording (disclosed; none is an owner decision)
1. **S3 one pass, same verdict**: the fact is computed in the same statement that builds the page and the home answer, with the predicate of `rpc_get_my_agreement_review(...).eligible`; the proof compares it with that authority for every party and every awkward state. The client falls back to the old path only for a page that does not answer for every finished Dogovor, never per row.
2. **S3 Home**: `ratings.due` is the server's count; `dueAgreementId` is present only when exactly one is due (what Početna opens); the number no longer depends on the Dogovori read.
3. **S4 page size 50** (the server accepts 1..100): a typical task has fewer applications than that, so it reads exactly as before - one page, no foot.
4. **S4 order by price and comparison read the rest**: a price order or a comparison over a part of the set would be wrong, so while either is on the rest of the set is read, a page at a time, up to the pager's bound (50 pages = 2,500 applications; beyond it "Prikaži još" continues by hand). "za izbor" (how many can still be chosen) is said only once every application is loaded; the count shown is the server's total.
5. **S4 revisions**: applications of two task revisions are never shown together. A first page whose revision differs from the task's is the whole list's refusal ("Zadatak se upravo promenio. Učitaj Prijave ponovo."); a LATER page read after the task changed turns the screen into the same refusal (unless a choice is already being decided - its sheet is what matters then) and the retry reads again from the top. The first-page check exists twice (in the read and as the shared mixed-revision check) on purpose: the second covers both the first and the later pages with the same words.
6. **S4 refresh and focus**: "Osveži prijave" reads the task and the first page again from the top; returning to the screen re-reads as many pages as were loaded (bounded); the app leaving the foreground forgets the rows.
7. **S4 states function**: the PKG-035a body is kept byte for byte (md5 pinned) plus ONE anchored edit; the whole-list function stays; nothing calls the new function except the new page.
8. Both servers keep the authority of their predecessors: SECURITY DEFINER, `search_path = pg_catalog`, EXECUTE for `authenticated` only (the private function for nobody); no table, column, constraint, trigger, policy, index or data change; no new status.
