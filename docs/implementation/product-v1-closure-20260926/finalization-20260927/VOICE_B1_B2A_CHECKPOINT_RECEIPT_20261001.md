## 7. Findings of this round
1. The deferred link-guard is also a `pg_constraint` row (`contype t`); the surface check named it (run 36783630762) and it is now excluded by exact identity and pinned explicitly.
2. A predecessor pin must treat a missing function as a mismatch (NULL is not distinct from NULL) — fixed earlier, before any DEV use.
3. The disposable chain's closure digest is not portable to DEV and not stable between runs; a digest is therefore computed inside the apply and pinned only where the state is known (the revert carries DEV's pre-application digest as a literal; its proof shows that the DEV file and the chain file differ in that one literal only).
4. The voice storage guard refuses a delete outside a closure (`MEDIA_ASSET_IMMUTABLE`), which is correct; the revert proof removes its own planted object by recreating the guard.
5. Generated files must not embed an OS-dependent path separator (the revert builder did, and the Linux runner caught it).
6. The erasure program digest hashes type oids (the argument type of a function over the voice table's row type), so a voice table that is dropped and created again binds a **different** digest; apply → revert → apply therefore ends with the same catalog but a newly bound digest. The revert itself restores the pre-application digest exactly, because the pre-application catalog contains none of those objects.
