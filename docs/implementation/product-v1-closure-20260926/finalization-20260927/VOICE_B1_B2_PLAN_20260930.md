## Decisions taken as design lead (the owner may overrule; owner-visible ones are marked)
1. **Storage and schema.** One new private table `private.agreement_voice_uploads_v1` (a clone of the photo table with audio columns: input at most 4 MiB, type audio/mp4, validated sha, bytes and duration 300 to 300,000 ms), a new private bucket `agreement-voice` (4 MiB, audio/mp4, NO storage policies), `agreement_messages.voice_asset_id uuid null` (no foreign key) with a kind-exclusive body CHECK, and guards that carry the closure-certificate prefix.
2. **Versioned reads (OWNER-VISIBLE compatibility decision).** New `..._page_v2` and `..._window_v2` emit `kind` TEXT / PHOTO / VOICE and a `voice` object `{assetId, durationMs, byteSize, contentType}`. The v1 readers keep serving old builds: a VOICE row goes out as kind TEXT with a fixed Serbian placeholder body, so an old client never fails the page (hiding the row would leave gaps in paging and acknowledgements). Only private test builds exist today.
3. **Send.** `rpc_send_agreement_voice_message_v1(expected_user, agreement, version, client_message_id, asset_id)`: empty body, exactly one READY voice asset, the same sender-global message key and lock, MESSAGE_RECEIVED in the same transaction, a positive membership check (the photo gate uses NOT IN, which passes when a participant is NULL: `PRIVATE_PHOTO_MEMBERSHIP_FINDING.md`; do not copy it), conflicts raise PT409.
4. **Upload and read services.** `rpc_agreement_voice_upload_service_v1` (the same eight operations, service_role only) and `rpc_agreement_voice_read_service_v1`. Rates 6 per minute and 60 per 24 h per account (rarer and larger than photos).
5. **Edge.** Add `agreement-voice-*` operations to `uskoci-media`: it already owns the Agreement claim / stage / dispatch / settle flow, the authorization and the safe codes, while a new function would break `scripts/prepare-v5-edge-payloads.cjs`, which requires exactly 11. Validation with `inspectVoiceM4a`, no sanitizer, no transcoding. The Edge deploy stays the owner byte-exact CLI route.
6. **Playback.** Bytes by an authenticated JSON POST (no URL ever), written to a temporary file in the cache directory, played with `expo-audio`, deleted on stop, blur and logout.
7. **Closure, export, retention in the SAME atomic candidate (the hard gate of the contract).** Redaction relation, scope and patch branch; the storage allow-lists (the SQL CHECK on closure actions, the blockers, the enumerator, the dispatch check, the patch check, the worker `closure.ts`); a blocker for a DISPATCHING voice upload with its client label; dataset catalog MEDIA_OBJECTS; export key `ownAgreementVoice` plus voice fields on `ownAgreementMessages` and a version tag bump; the roster extension and a voice surface helper in the digest (bucket row, storage policies, function metadata; the B3c `agreement_invalidation_surface_v1` is the template); the re-bind in the three places.
8. **Support evidence.** A voice message is not capturable as support media in V1; its support preview is a fixed label, never an empty string.
9. **Retention classes.** Reuse AGREEMENT_MESSAGES and MEDIA_OBJECTS; no new class (a new required class would reopen the schedule). The legal drafts LEG-09/10/11/12 say voice is not stored: their text is the owner decision; this plan only flags them.

## Places where a third kind breaks silently (from the inventories; each needs a test)
**Server.** B3a line 68 and B3b line 102 derive kind from `photo_asset_ids` (a VOICE row would leave as TEXT with an empty body, which the decoder rejects); `agreement_messages_body_photo_check` rejects an empty-body voice row; the photo message guard returns early when there are no photos, so a voice row would be unchecked and mutable; the closure storage allow-lists name only `profile-media` and `data-export-artifacts` (migration 20260912230039 line 113 STORAGE_INVENTORY_UNSUPPORTED, migration 146 lines 387-389 and 567, `supabase/functions/uskoci-account-closure-worker/closure.ts` lines 6 and 22, the retention registry description); Edge constants for image type and size, the exact-shape validators, the shared `busy` flag and the 25 s timer; `scripts/prepare-v5-edge-payloads.cjs` requires exactly 11 functions.

**Client.** `message()` in `agreementMessageHistoryService.ts` demands exactly nine keys and only TEXT or PHOTO and nulls the page on one bad row; `agreementMessageClientService.ts` lines 29 and 42 (empty body and photo RPC choice); `agreementOutbox.ts` `bodyValid` (an empty body never reconciles), `sameCommand`, and `read()` throwing for the whole record on an unknown entry (older builds too), so voice entries need their own key; `AgreementChat.tsx` lines 309, 333, 513-518, `messageSpoken`, `layoutIdentity`, the support `previewValid`; `dogovor/[id].tsx` lines 212-217 (reconcile mapper) and 266-281 (Back handler, no recorder awareness) plus the background fence; the logout purge knows two prefixes and the photo journal is never purged; route suites mock the hooks, so a new hook or component needs a mock in five or more suites and there is no `expo-audio` mock; Jest does not type-check, so a new required field fails only `tsc` in CI; the control tracker (`scripts/control/osvezi.mjs`) turns the server light red for an `rpc_*` literal DEV does not have yet; `pkg002-app-config.test.ts` pins the image-picker microphone copy while both plugins write `NSMicrophoneUsageDescription`.

## Findings of the proofs (2026-09-30) that change the plan
1. **A predecessor pin must not treat a missing function as equal to an absent alternative** (NULL is not distinct from NULL): found by the drift proof, fixed in the candidate before any DEV use.
2. **The disposable chain is DEV-equivalent only through the B3c application.** The B1-b candidate accepts the pre-B24 body of the two functions B24 part 2 rewrote (`rpc_start_account_closure_execution`, `support_reference_v5`: a conflict code only, other sites than the anchors) so the same bytes run there; the DEV-form wrapper (B1-d) must pin the DEV bodies exactly, as the B3c application did.
3. **The storage guard of the voice bucket refuses only an ACCOUNT-WIDE hold** (it is also a hard closure blocker); a hold scoped to one AI conversation never protects a voice object. The B1-a guards and the asset guard now carry the closure-certificate prefix like every other trigger on the erasure roster.
4. **The Edge function uses a realm-independent error test** (`row(error)?.message`), not `instanceof Error`, so the validator's error mapping is identical in Deno and in the offline harness.
5. **Order of the owner's actions for B1-d**: first the Edge deploy of `uskoci-account-closure-worker` (it accepts a superset: an unknown bucket was refused before, `agreement-voice` with its exact object shape is admitted now) and `uskoci-media`, then the DEV package (one atomic candidate = B1-a + B1-b with exact DEV pins and the three-place re-bind computed inside the same transaction, plus its receipt). Applying the package first would only make a closure with a voice object wait until the worker is deployed; it cannot lose data.
6. **Support cannot hear a reported voice message in V1** (the report carries the fixed label and the exact message identity and revision). Whether a moderator may ever listen is a product and privacy decision for the owner.
