**No site is kept on 40001.** The owner's rule is to keep 40001 only where it stands for a real serialization/retry case. A real one is raised by Postgres itself (for example `could not serialize access`), never by a function body, and those are not touched. Every site here compares something the caller or a worker supplied (an expected revision, an attempt/lease/generation token, a displayed digest, an idempotency key) with the stored state, or reports that a write found nothing to write; repeating the same call re-runs the same comparison against state that has already moved on, and raises the same code again (for D5 the repeat reaches the D1/D2 check first). D6 (`MEDIA_STORAGE_UNCONFIRMED`, 4 sites) is the closest to "try again later", but the caller that may try later is the Edge media worker, and it must do so with its own delay: an immediate unbounded retry inside PostgREST is exactly the defect.
