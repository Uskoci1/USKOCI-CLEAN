## 2. Who may write

Skeptic correction R07: COMPLETED is also reached by the 48h requester auto-completion (rpc_tick_auto_completion, service-only) and by requester confirmation after a reported problem; there is no review deadline, so a comment becomes possible after both paths; default = allowed (same as stars), flagged for owner confirmation [DN-04, D-DEC-11]. ## 3. One review per side
CANONICAL_RULE: unique(agreement_id, reviewer_account_id) = at most one review per participant per Agreement, so at most two per Agreement (one per side); retry of the same direction is idempotent (reviewer, client_request_id) and never creates a second review [R03, R10, CR-06]. The review is an immutable single command (trigger REVIEW_IMMUTABLE, client copy 'Uspesna ocena se ne menja'). PROPOSAL consistent with canon: the comment travels ATOMICALLY in the same command as the stars; there is no separate comment step. Consequences to state to the owner: (1) a star-only review (any installed APK, or a person who skips the text) can NEVER gain a comment later, because that would be an edit, which canon does not define [R28, DEC-5, C-11]; (2) the 7 existing DEV reviews stay comment-less forever; (3) ratingDue / Home 'Cekaju te' predicates stay unchanged because they are defined by review-row existence, so a comment does not alter them [E21, M31]; (4) the review row and its input_hash formula stay byte-identical, the comment lives in its own row keyed 1:1 by review_id (PK), so 'one review per side' remains the single rule and 'at most one comment per review' follows from the PK.

## 4. Text rules - length, validation, strictness (all PROPOSAL; the canon names no number)
PROPOSAL - canon names NO number or validation rule for 'short' (L-017 says only 'short'/'bounded input') [DN-02, M27, C-32]; every item below needs the owner's word before application. (a) Optional: no preselected text, no obligation, empty/whitespace-only means NO comment (omitted, never stored as an empty row) [CR-05]. (b) Length: 1..500 characters counted as code points after btrim (char_length), plus octet_length <= 2000; 500 matches the existing close-search/QA bound and stays below 1000 (application message), 2000 (chat, safety narrative) [DN-02, M11]. (c) Strictness: server REJECTS rather than silently normalises (text must equal btrim(text), no NUL, no control characters except LF; reject CR/TAB, bidi controls U+200E/U+200F/U+202A-202E/U+2066-2069, U+200B, U+FEFF, U+2028/2029; allow U+200D and U+FE0F so emoji sequences work) because [[:cntrl:]] alone misses U+202E and U+200B [M10] and a server that normalises would break the client's readback-equality check and make a successful save look like REVIEW_INVALID_RECEIPT [C-10]. Client sends trimmed NFC text; count unit and rule written once into the server contract and ONE shared client helper (today the helper is duplicated in 5 services) [M11, C-10]. (d) Type strictness: p_comment is jsonb and must be JSON null or a JSON string (as p_rating is a strict JSON number). (e) Deterministic contact floor, NO AI and NO paid call: reuse private.ru4b_public_floor_reason(text) (IMMUTABLE, uncertified, not in the 88) to reject e-mail, links, @handles and phone numbers with ONE plain-Serbian code REVIEW_COMMENT_CONTACT_NOT_PUBLIC; measured limits: it flags '064 123 4567' and e-mails but MISSES spelled-out numbers and obfuscated addresses, so it is a floor, not a guarantee; the Q&A AI policy gate is NOT reused [M09, C-24 corrected, DN-12]. (f) Errors: validation raises 22023 with names REVIEW_COMMENT_INVALID / REVIEW_COMMENT_TOO_LONG / REVIEW_COMMENT_CONTACT_NOT_PUBLIC; no 40001 anywhere; any deterministic conflict that appears must use PT409 [CE-5]. Every new name needs an entry in the client errors map or it degrades to the generic unknown-outcome text [C-09]. The legacy 5-argument path must never raise a new name [R18 addition]. (g) Idempotency: star row input_hash formula unchanged ({agreementId,target,rating,tags}); the comment is bound by comment_sha256 stored in the comment row; same request id + different comment (or comment added to a stored star-only review) = REQUEST_ID_REUSED. This keeps the 7 stored hashes, old-APK lost-ack replays and replays through either function byte-compatible, and keeps the free-text fingerprint inside the erasable row [R10, A-hash, CZ-5].
