# Paid probe: granice poziva, naloga i oporavka

Read-only pregled 2026-09-13, nad fizičkim izvorima uz HEAD `2ece7eec13fba40396c9d05f7ab441b4adad4ea4`. Nema provider/metadata poziva, čitanja ključeva, izmene aplikacije/SQL/config-a ili live provere. Izmenjeni su samo ovaj izveštaj i [PAID_PROBE_PLAN](PAID_PROBE_PLAN.md). Kasniji source ili stvarno deploy-ovane verzije moraju biti provereni u root batch-u.

**Sa tačnom predloženom konfiguracijom svih pet provider ulaza prolazi SQL127 pre novog Gemini I/O. Nije pronađen automatski novi plaćeni pokušaj pri oporavku istog V5 command-a.** USD 2.90 i broj probe ipak nisu dodatna server kvota: to je obim kontrolisanog postupka. Server ograničava zbir rezervacija na USD 5 i naloge koji smeju da steknu novu rezervaciju. Ne ograničava batch/endpoint/uređaj, sve korisničke SQL akcije ili javnu publiku.

SQL127 u svim ovim rezervacijama zahteva: service-only RPC; tačan kind/cost; global enabled i rok važenja; `retired_at is null` za upravo Auth-proveren account; postojeći neobrisan Auth user; open closure barrier; preostali globalni prostor. Isti UUID drugog naloga/kind-a daje conflict, isti originalni operation daje `admitted=false/replay=true`. Nema provider poziva na taj replay. Lock jedne globalne vrste serijalizuje rezervacije različitih naloga. To štiti budžet od novih poziva neodobrenih postojećih korisnika, ali ih ne isključuje iz ostalog proizvoda.

## 4. Gašenje i provera pre live odobrenja

Pre prve probe root potvrđuje konačne source/deploy verzije, tačan provider config, pun aktivni allowlist, postojeće rezervacije i nerešene/aktivne pokušaje. SQL127 je ledger rezervacija, nema STT lifecycle status kojim bi sam dokazao da su svi socket-i zatvoreni. Posle svake probe sačekati njen potvrđeni terminalni/unknown ishod i troškovnu evidenciju; unknown zaustavlja narednu plaćenu probu, ne refunduje slot.

Zatvaranje admission-a sprečava sticanje **novih** rezervacija u pregledanom Gemini config-u. Već rezervisan HTTP zahtev ili otvoreni govor može završiti posle te promene; nema periodičnog server recheck-a flag-a u aktivnom toku. Posle uspešnog release-a ne gasiti admission između STT finala i očekivanog AI submit-a ako batch želi da proveri pun korisnički ugovor. Taj par već ima oba slota uračunata unapred. Ne tvrditi da gašenje flag-a poništava već naplaćen poziv, sačuvan ALLOW, canonical publish/dispatch ili QA READY submit.

P1/P3/P4 ostaju zasebna pravna/retention/processor spremnost; 124/125 koriste postojeće owner-approved RS produktne odluke. Nisu razlog za izmišljeni publication blocker niti potvrda da je platforma pravno spremna za stvarni javni rad. Precizna publika i realni dispatch pripadaju odobrenju konkretne objave iz [PUBLICATION_ACTIVATION_READINESS](PUBLICATION_ACTIVATION_READINESS.md).

Ovo je ograničen source review, ne novi test PASS za live konfiguraciju, runtime model dostupnost, privatnost cele platforme ili stvarnu Google naplatu. Nijedan postojeći korisnički nalog nije dodavan/uklanjan sa liste niti je aktiviran novi gate.
