## Transport safety (the round-1 blocker) and how the application text MUST be sent
A connector deploy (`execute_sql` / `apply_migration`) RESOLVES the text of a unicode escape (backslash, `u`, four hex digits) before the statement reaches Postgres (measured read-only on 2026-10-01; project memory `uskoci-edge-deploy-via-connector-caveat`). The first candidate carried 47 of them, which would have changed a pinned body and every md5. Now **no generated file carries an escape text, a non-ASCII byte, a carriage return or a tab**: every character class is BUILT from `chr(<decimal>)` pieces, the Serbian letters of the legacy event text and of the captured pre-image are `chr(353)` and a restore marker plus `replace(..., chr(382))`. Enforced by `render()` (generation fails), by a static unit test over the committed files, by a simulated connector round trip, and by a CI step (CRLF / non-ASCII / escape scan, whatever the checkout's line endings).

**The integrity guard (the Voice B1 method), as hardened in round 2.** `python supabase/proofs/d12/build_d12.py --wrap supabase/candidates/d12_review_comment.sql --wrap-out <path>` writes ONE text: a DO block, then the candidate. The DO block runs first, inside the database, and raises the named error `D12_APPLY_TEXT_INTEGRITY` (SQLSTATE 55000) before anything else runs unless ALL of these hold: (1) the characters of the received statement from position `start` (absolute: the end of the guard) for the length of the candidate's span hash to the sha256 of the candidate WITHOUT its trailing line feeds; (2) whatever FOLLOWS that span is nothing but line feeds and `--` comment lines (the pattern `^(\n|--[^\n\r]*)*$`; a carriage return ends a comment in the PostgreSQL lexer, so it is not allowed inside one); (3) nothing precedes the guard (anything before it shifts the start and fails (1)). So the text may be sent with or without its final line feed, and the trailer that the `execute_sql` connector appends to every statement (a blank line, then `-- source: POST /mcp`, `-- user: ...`, `-- date: ...`; measured read-only with `current_query()`, its own date stamp reads 2026-10-01T23:42Z) is accepted; a changed or truncated byte of the candidate, a prefix, a space, a statement or a block comment after it is refused. The text must be sent as ONE statement text, guard first, with nothing before it. The proof runs the guard on the real database with each of these cases (P2). **Whether a given connector delivers the text without changing a byte (JSON string escaping of backslashes included) is not proved here:** the guard turns any change into a refusal and the postflight turns it into a named problem, so a bad transport cannot apply a different text.

## Text rules (closed, explicit, documented; a product-neutral safety rule, not an owner decision)
500 code points, 2000 octets, LF allowed, trimmed (the server rejects, never normalises). Every class is an EXPLICIT list built from `chr()` pieces; nothing depends on the database locale.

- **Forbidden anywhere** (REVIEW_COMMENT_INVALID): the C0 controls except LF (U+0001..U+0009, U+000B..U+001F), DEL and the C1 controls (U+007F..U+009F), the line and paragraph separators U+2028..U+2029, and **every Default_Ignorable_Code_Point of Unicode 17.0** except the four allowed-inside groups below. That is: the Arabic letter mark U+061C, the Hangul / Khmer / Mongolian fillers and free variation selectors (U+115F..U+1160, U+17B4..U+17B5, U+180B..U+180F), ZWSP U+200B, the directional marks, embeddings and isolates (U+200E..U+200F, U+202A..U+202E), the whole block U+2060..U+206F (word joiner, invisible operators, **the reserved U+2065**, isolates, deprecated format characters), U+3164, the BOM U+FEFF, U+FFA0, the reserved U+FFF0..U+FFF8, the shorthand format letters U+1BCA0..U+1BCA3, the musical format characters U+1D173..U+1D17A and the whole plane-14 block U+E0000..U+E0FFF (the TAG characters, **the ideographic variation selectors U+E0100..U+E01EF** and the reserved rest). Two format-control blocks that render as nothing but are not default-ignorable by definition are forbidden as well: the interlinear annotation characters U+FFF9..U+FFFB and the Egyptian hieroglyph format controls U+13430..U+1343F. **Stated consequences:** the three subdivision-flag emoji (made of tag characters) and every ideographic variation sequence (CJK variant glyphs) are refused; a code point that a later Unicode version makes default-ignorable is not covered until the generator table is extended (the offline unit test re-reads `\p{Default_Ignorable_Code_Point}` in the running Node and fails if one is outside the closed classes). Code points that merely MAY render as nothing in some fonts (private use, noncharacters, unassigned code points) are NOT covered: documented residual, moderation is manual.
- **Allowed inside a sentence** (default-ignorable, but needed): the soft hyphen U+00AD, the combining grapheme joiner U+034F, ZWNJ and ZWJ (U+200C..U+200D, emoji sequences) and all sixteen variation selectors U+FE00..U+FE0F (emoji presentation). Together with the braille blank U+2800 they are removed from the copy the contact floor reads.
- **"No comment"** (nothing is stored, no error): a text made ONLY of blank characters: the ASCII white space U+0009..U+000D and U+0020, U+0085, the Unicode separators U+00A0, U+1680, U+2000..U+200A, U+2028..U+2029, U+202F, U+205F, U+3000, and the allowed-inside groups with the braille blank. The ASCII class is listed explicitly (round 2: the old class started with the POSIX `[[:space:]]`, which also matches U+001C..U+001F in en_US.UTF-8 and not in a C locale; measured on DEV on 2026-10-02: the database locale is en_US.UTF-8 and `chr(28) ~ '^[[:space:]]$'` is true): **U+001C..U+001F are NOT blank**, so a comment made of one of them alone is REVIEW_COMMENT_INVALID in every locale. All sixteen variation selectors alone mean "no comment" (the old class stopped at U+FE0E..U+FE0F, so a lone U+FE00..U+FE0D was refused only by accident, with the misleading name REVIEW_COMMENT_CONTACT_NOT_PUBLIC).
- **Contact floor** (`ru4b_public_floor_reason`, live PKG-029c): runs on the text as sent AND on an NFKC copy without the invisible characters above and with Arabic-Indic and Persian digits mapped to ASCII; the STORED text is the original. A comment that holds a forbidden invisible character is refused as INVALID BEFORE the floor runs, so a phone number can no longer be split by one of them.

## Reader semantics
Keyed by PROFILE id like `rpc_get_public_profile`, gated in the same order; per row it also hides a hidden comment, a closure-restricted author, **a block between the VIEWER and the author (either direction)**, another world and a non-ACTIVE author profile. **There is deliberately NO viewer-independent block gate** (round-1 blocker): a gate on "author blocked subject or subject blocked author" is true for either direction, so either party could censor or re-publish the text for EVERY viewer by toggling a block, the edit/delete path the owner forbade through a side door; hiding for everyone is the audited moderation HIDE only. `agreementId` is returned only to the reviewed person (so they can report through the existing channels). The reader returns no account id **except as embedded in `avatarPath`, exactly as `rpc_get_public_profile` returns it** (on DEV the first path segment of an avatar equals the account id; the owner accepted that disclosure on 2026-09-22; the proof gives one author such a path).

**The symmetric rule has a second direction (round-2 finding, item 16 below): the shadow comment.** A block is symmetric for the per-row gate, so when the AUTHOR blocks the REVIEWED person (or blocked them before writing), that person is the viewer of a blocked pair and no longer sees the comment about them; every third viewer still does. The proof pins this as the implemented behaviour (P6 gates `AUTHOR_BLOCKS_SUBJECT` and `BLOCKED_AUTHOR_WRITES_HIDDEN_FROM_THE_BLOCKER_ONLY`).

17. **THE PUBLIC AGGREGATE NEXT TO INDIVIDUAL RATINGS (round-2 finding).** `reviewCount` and `averageRating` (rounded to 2 decimals, in `rpc_get_public_profile` and `rpc_get_account_reputation`) stay public and unchanged, and the reader now publishes the individual rating of every COMMENTED review.
