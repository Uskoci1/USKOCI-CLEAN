## After the first CI run (36949455489, source f8e36e52)
What the run proved on a real database: the pin gate (47 of 47 pins equal DEV), the atomic application with the certificate re-bound, old-client parity, the gates, visibility, RLS, moderation, both real closures, the export, the revert and the reapply, the weakening probes. Two checks were red; neither was a defect of the candidate (`candidateChanged: false`, the four generated files and the manifest are byte-identical to before):
1. **`ANON_IDENTICAL` (a test defect).** The platform's own refusal quotes the called function (`permission denied for function rpc_submit_agreement_review` against `... rpc_submit_agreement_review_v2`), so two functions can never answer byte-identically. The comparison now masks the called function's name as a whole identifier, requires each message to name the function that was called, and requires status, SQLSTATE and the rest of the sentence to be identical (`lib.sameOutcomeMaskingFunction`); each refusal is also pinned exactly.
2. **`neighbour_inner_uDFFFF` came back as `ab` (a transport defect).** U+DFFFF is the last code point of plane 13, a Unicode noncharacter, and the code point just below the forbidden plane-14 block. The function ACCEPTED the text and returns its input untouched, but the proof read back `ab`. Located by elimination, with evidence: the candidate body returns `v` unchanged (read), PostgreSQL 17.6 on DEV keeps the character through `to_jsonb`, `jsonb_to_recordset`, `#>>`, `jsonb_out`, `convert_from(decode(.., 'base64'))` and `encode(convert_to(..), 'hex')` (read-only SELECTs, 75 canaries of which 66 noncharacters, 75 of 75 byte-exact), libpg_query keeps it in a quoted constant, and Node 24.18 carries all 1,112,063 Unicode scalar values byte-exact through a child process in both directions and through `JSON.stringify`/`JSON.parse`, including the exact matrix payload and a PostgreSQL-shaped answer. What no offline run can reach is the `psql` process on the runner (stdin, client encoding, stdout), the only hop left, so the exact hop is **not established**. The proof therefore no longer depends on it: every text travels as ASCII both ways (base64 in, decoded in SQL; the verdict is the hex of the returned octets and the count of characters, plus the SHA-256 of what the database decoded), a script that is not ASCII is refused before it is sent, and a new check (`P4_THE_TEXT_TRANSPORT_OF_THE_MATRIX_IS_ASCII_ONLY_...`) asserts the ASCII path byte-exact for all 66 noncharacters and MEASURES the raw input hop, the raw output hop at psql/the server and at the Node decoder separately, recording `psql --version`, `client_encoding`, `server_encoding` and the locale variables in `report.phases.transport`; a loss on a raw hop is reported in `report.gaps` and names the hop and the code points. The next run therefore names the hop, whatever it is.
3. **Noncharacters are explicit matrix cases (decision recorded).** U+FDD0..U+FDEF and U+xFFFE/U+xFFFF of the 17 planes (66 code points) are valid scalar values; the closed forbidden class does NOT name them and is NOT widened here (a product rule already reviewed, `README_D12_CANDIDATE.md`, "Text rules"). They are cases whose expectation is DERIVED from the class tables (inside a sentence and, for eight of them, alone: accepted and returned byte for byte; one text with a plane-14 tag block member next to one is refused whole), plus the residual `residual_phone_split_by_a_noncharacter` (a noncharacter splits a digit run like any visible character, accepted today and pinned, not blessed) and one `residual_noncharacters` line in the report. Three of them also go through the real PostgREST path and are compared as hex in the stored row.
The offline tests reproduce the observed symptom with a lossy hop (a text that loses noncharacters), show that the old raw scripts change under it and every ASCII script does not, and that the verdict function reports exactly the first-run observation.
